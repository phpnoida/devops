# DevOps Learning Repository

## Purpose
This is a personal DevOps learning repository. The goal is to study each topic in depth, take detailed notes in Markdown files, do hands-on practicals, and solve real-world-style questions that simulate a company environment.

## Repository Structure
Each directory is a dedicated topic area:

| Directory | Topic |
|-----------|-------|
| `linux/` | Linux fundamentals and administration |
| `git/` | Git version control |
| `shellscripting/` | Bash/shell scripting |
| `docker/` | Docker and containerization |
| `k8s/` | Kubernetes orchestration |
| `ansible/` | Ansible automation and configuration management |
| `terraform/` | Terraform infrastructure as code |
| `jenkins/` | Jenkins CI/CD |
| `githubactions/` | GitHub Actions CI/CD |
| `devsecops/` | DevSecOps practices and security |
| `monitoringObservality/` | Monitoring and observability (Prometheus, Grafana, etc.) |

## Learning Approach
- **Notes**: Each topic has in-depth Markdown notes covering concepts, commands, and explanations
- **Practicals**: Hands-on exercises and configurations within each topic folder
- **Q&A / Scenarios**: Real company-like questions and scenarios to simulate production environments
- **Depth over breadth**: Topics are studied thoroughly, not just at surface level

## How to Help
- When reviewing or creating notes, keep them detailed, well-structured, and practical
- For practical exercises, simulate real-world scenarios (production-grade configurations, troubleshooting, best practices)
- For Q&A, frame questions as if they come from real interviews or on-the-job situations
- Suggest improvements to notes if something important is missing
- Use proper Markdown formatting with code blocks, tables, and clear headings
- When explaining concepts, connect theory to real-world usage in companies
